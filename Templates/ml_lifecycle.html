The Machine Learning System Lifecycle

Building a production ML system is far more than fitting a model in a notebook. It requires an orchestrated pipeline from raw ingestion to low-latency serving, robust against training-serving skew.

The 8 Stages of PlacementPredict Lifecycle

End-to-End Pipeline
01. Raw Data

Raw Data Ingestion

Ingestion of tabular campus records. Located in Data/placement_predict_50k Dataset.csv.

02. Cleaned

Cleaned Dataset

Outlier detection, duplicate checks, schema validation in load_data.py.

03. Features

Engineered Features

ColumnTransformer handles median imputation, StandardScaler/MinMaxScaler, and One-Hot/Ordinal encodings.

04. Splits

Training & Test Sets

Stratified 80/20 splitting preserves placement class balance without leakage.

05. Training

Trained Estimators

Training M2 Linear & M3 Tree algorithms in supervised_models.py.

06. Artifacts

Packaged Artifact

Serialized production pipelines stored in models/saved_models.joblib.

07. Endpoint

Served Endpoint

REST inference endpoint POST /api/predict serving instant JSON predictions.

08. Monitoring

Monitoring & Retraining

Benchmark logging in models/benchmark_results.json with triggerable retraining.

The Training-Serving Boundary & Skew

Training-Serving Skew is the discrepancy between model performance in development versus real-world production serving. It is the #1 cause of silent failures in machine learning systems.

How PlacementPredict Eliminates Skew:
  • Raw features are transformed at inference time by the exact same serialized preprocessor fitted on training data.
  • No ad-hoc manual scaling or encoding in client web forms.
  • Feature statistics ($\mu, \sigma$, categories) remain locked inside the packaged joblib artifact.

Why Feature Stores Exist: In enterprise systems (e.g. Feast, Hopsworks), feature stores unify batch feature computation for model training with ultra-low latency point lookups for online serving.

ML Paradigms & Curriculum Scope

Supervised vs Unsupervised vs RL:
  • PlacementPredict is Supervised Learning: We learn from historical labeled records $(X, y)$ where true outcomes (Placed/Unplaced, Salary) are known.
  • What it is NOT: It is not Unsupervised (clustering unlabeled patterns) or Reinforcement Learning (agent receiving delayed rewards in an environment).
Curriculum Division of Ownership:
  • This Course (ML): Classical ML, regularized linear models, tree ensembles, tabular ML engineering.
  • DLAC: Deep Learning architectures (MLPs, CNNs, Transformers).
  • GALE: Generative AI, VAEs, GANs, Diffusion models.
  • NLPL: Natural Language Processing, Large Language Models (LLMs).
